30 CONTENT-OS Privacy policy

Privacy policy

Effective 30 October 2026

Content-OS is a personal Windows desktop app. It runs on its developer's own PC and is used only with his own YouTube channel and Instagram account. This policy explains exactly what it does with data.

1. Who runs Content-OS

Content-OS is built and used by Alok Mishra, the creator of Bas 30 Din, as an individual. It is not a company service. Contact: hello@bas30din.com.

2. What the app does

It organises video projects on the PC, keeps a local publishing schedule and, only after the owner approves an exact video, account and time, uploads that video to YouTube or Instagram using their official APIs. It also keeps a local history of what was published and any errors.

3. Google and YouTube data it uses

Content-OS uses YouTube API Services. When the account owner connects YouTube, Content-OS requests these Google permissions:

  • https://www.googleapis.com/auth/youtube.upload: to upload approved videos and set their thumbnails.
  • https://www.googleapis.com/auth/youtube.readonly: to read the channel ID and name, so it can confirm the connected channel is the approved one, and to read the upload, processing and privacy status of videos it uploaded.

It does not request permission to delete or edit existing videos, manage comments, or read analytics. If Google ever returns broader access, Content-OS refuses to store it.

From Google it receives an access token, a refresh token, the channel ID and name, and status information about the videos it uploads.

4. How YouTube upload authorization works

The owner signs in on Google's own page in the browser and approves the permissions above. Content-OS uses Google's recommended flow for desktop apps, with PKCE, and receives the result on the PC itself (a local address, 127.0.0.1). It checks that the signed-in channel is the approved channel before saving anything. An access token lasts about an hour; Content-OS uses the refresh token to get a new one automatically.

Each upload needs a separate approval of the exact file, account and time. New YouTube uploads start as private. A scheduled video uses YouTube's own publish time.

5. Instagram data it uses

For Instagram, Content-OS connects to the owner's Instagram professional account through Meta's official Instagram API, using permissions such as instagram_business_basic and instagram_business_content_publish (Instagram Login), and for direct uploads from the PC, instagram_basic, instagram_content_publish, pages_show_list and pages_read_engagement (Facebook Login for Business). It reads the account ID and username to confirm the right account, the account's publishing limit, and the status and link of Reels it publishes. Instagram publishing is in testing.

6. Where credentials are stored

All tokens, and the Google OAuth client details, are stored only on the owner's Windows PC, in files inside the Content-OS folder. They are encrypted with Windows Data Protection (DPAPI), which ties them to the owner's Windows user account. There is no Content-OS server and no cloud copy.

7. How data is protected

  • Credentials are encrypted with Windows DPAPI and never written in plain text.
  • Tokens and sign-in codes are not written to logs or shown on screen.
  • The app only connects over HTTPS to Google and Meta API addresses on a fixed allow list.
  • It checks the account identity before storing a sign-in and before each publishing job.

No system is perfectly secure. Anyone with access to the owner's Windows account could use the stored sign-in.

8. Local processing and sharing

Everything runs on the owner's PC. Content-OS has no analytics, telemetry, advertising or tracking, and it does not sell or share data with anyone.

The only data that leaves the PC goes directly to the platform you are publishing to, and only to carry out an approved action: to Google (YouTube) the video file, title, description, thumbnail, privacy and schedule settings; to Meta (Instagram) the video file and caption. Those platforms then handle that content under their own terms and privacy policies.

9. Revoking access

  • Google: remove Content-OS at myaccount.google.com/permissions (Google's security settings page).
  • In the app: Settings, Accounts, Disconnect an account. This deletes the stored sign-in from the PC and, for YouTube, can also ask Google to revoke it.
  • Instagram: in Instagram, Settings, Website permissions, Apps and websites; for Facebook Login, Facebook Settings, Business integrations.

10. Retention and deletion

Stored sign-ins stay on the PC until they are disconnected, revoked or expire. The local publishing history (titles, captions, scheduled times, platform IDs, links and status) and project files stay in the Content-OS folder, and in the owner's own backup drive, until the owner deletes them. Nothing is kept on any Content-OS server, because there is none.

To delete everything: disconnect the accounts in the app, revoke access as above, then delete the Content-OS folder. Videos already published live on YouTube or Instagram and are deleted there. For any question or deletion request, email hello@bas30din.com.

11. Google API Services User Data Policy

Content-OS's use and transfer of information received from Google APIs follows the Google API Services User Data Policy, including the Limited Use requirements. Google data is used only to upload and check the owner's own videos, is never used for advertising, and is never transferred to anyone else.

Because Content-OS uses YouTube API Services, the Google Privacy Policy also applies to data Google processes.

12. This website

These information pages set no cookies and contain no analytics. They are hosted by Cloudflare, which processes standard request data, such as IP addresses, to deliver web pages.

13. Changes

If Content-OS changes how it handles data, this page will be updated and the effective date above will change.
