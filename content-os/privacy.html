30 CONTENT-OS Privacy policy

Privacy policy

Effective 4 November 2026 (replaces the version of 30 October 2026)

Content-OS is a Windows desktop app for creators. It runs on the creator's own PC and is used only with the creator's own YouTube channel and Instagram account. This policy explains exactly what it does with data.

1. Who runs Content-OS

Content-OS is built by Alok Mishra, the creator of Bas 30 Din, as an individual. It is not a company service. Today it is used by Alok and by creators he invites. Contact: hello@bas30din.com.

2. What the app does

It organises video projects on the PC, keeps a publishing schedule and, only after the creator approves an exact video, account and time, publishes that video to YouTube or Instagram using their official APIs. It keeps a history of what was published, any errors, and the public view, like and comment counts of those posts.

3. Google and YouTube data it uses

Content-OS uses YouTube API Services. When a creator connects YouTube, Content-OS requests these Google permissions:

  • https://www.googleapis.com/auth/youtube.upload: to upload approved videos and set their thumbnails.
  • https://www.googleapis.com/auth/youtube.readonly: to read the channel ID and name, so it can confirm the connected channel is the approved one, and to read the status and public view, like and comment counts of videos it uploaded.

It does not request permission to delete or edit existing videos, manage comments, or read private analytics. If Google ever returns broader access, Content-OS refuses to store it.

From Google it receives an access token, a refresh token, the channel ID and name, and status and count information about the videos it uploaded.

4. How YouTube sign-in and uploads work

The creator signs in on Google's own page in the browser and approves the permissions above. Content-OS uses Google's recommended flow for desktop apps, with PKCE, and receives the result on the PC itself (a local address, 127.0.0.1). It checks that the signed-in channel is the approved channel before saving anything. An access token lasts about an hour; Content-OS uses the refresh token to get a new one automatically.

Each upload needs the creator's approval of the exact file, account and time. New YouTube uploads start as private. A scheduled video uses YouTube's own publish time, so it can go public at that minute even if the PC is off.

5. Instagram and Facebook data it uses

For Instagram, Content-OS connects to the creator's Instagram professional account through Meta's official Instagram Graph API with Facebook Login for Business. It requests instagram_basic, instagram_content_publish, pages_show_list and pages_read_engagement.

It uses them to read the Instagram account ID and username (to confirm the right account), the Facebook Page linked to it, the account's publishing limit, and the status, link and like and comment counts of Reels it publishes, and to publish the Reels the creator approved. It does not read messages, followers' personal data or other people's content, and it never likes, follows or comments.

The sign-in happens on Facebook's own page in the browser and returns to the PC (a local address, localhost:8767). Content-OS checks the token, the app and the account before saving anything.

6. The Content-OS cloud helper

Content-OS has one small online part, the cloud helper, which runs on Cloudflare (Cloudflare Workers, KV and R2). It is used for two things only:

  • Finishing the Facebook sign-in. Facebook gives a one-time sign-in code; the helper exchanges it for a sign-in token using the Meta app secret, which is kept only on Cloudflare, and sends the token straight back to the creator's PC. The helper does not keep the code or the token.
  • Posting Instagram Reels while the PC is off (only if the creator turns this on in Settings, Publishing). For each scheduled Reel the PC uploads the video file to a Cloudflare R2 storage folder at a long random link that is not listed anywhere, and gives the helper the Instagram account ID, the sign-in token, the caption and the time. At the time, the helper asks Instagram to fetch the video from that link and publishes it.

When the Reel is posted, fails or is stopped, the helper deletes the video file and erases the sign-in token from the job. The rest of the job record (account ID, caption, time, result and post link) is deleted automatically after 30 days. Only the creator's own PC holds the key to add or read jobs.

7. Where credentials are stored

Sign-ins are stored on the creator's Windows PC, inside the Content-OS folder, encrypted with Windows Data Protection (DPAPI), which ties them to the creator's Windows user account. The only copies outside the PC are the short-lived ones described in section 6 (a token inside a waiting Instagram job, erased when the job ends) and the Meta app secret on Cloudflare.

8. How data is protected

  • Credentials are encrypted with Windows DPAPI on the PC and are never written in plain text.
  • Tokens and sign-in codes are not written to logs or shown on screen.
  • All connections use HTTPS, only to Google, Meta, Cloudflare and the Content-OS cloud helper.
  • The account identity is checked before a sign-in is stored and before each publishing job.

No system is perfectly secure. Anyone with access to the creator's Windows account could use the stored sign-in.

9. Sharing

Content-OS has no analytics, telemetry, advertising or tracking, and it does not sell or share data with anyone.

Data leaves the PC only to carry out an approved action: to Google (YouTube) the video file, title, description, thumbnail, privacy and schedule settings; to Meta (Instagram) the video and caption; and, when the creator uses it, to the cloud helper on Cloudflare as described in section 6. Google, Meta and Cloudflare handle that data under their own terms and privacy policies.

10. Revoking access

  • In the app: Settings, Accounts, Disconnect. This deletes the stored sign-in from the PC and, for YouTube, also asks Google to revoke it. Stopping a scheduled Reel also stops its cloud job.
  • Google: remove Content-OS at myaccount.google.com/permissions.
  • Facebook and Instagram: Facebook Settings, Business integrations (or Apps and websites), then remove the Content-OS app (shown by Meta as Secret Knook Poster).

11. Retention and deletion

Sign-ins stay on the PC until they are disconnected, revoked or expire. The publishing history and project files stay in the Content-OS folder, and in the creator's own backup, until the creator deletes them. Cloud helper data is deleted as described in section 6.

How to delete all of your data, including a request by email, is on the data deletion page.

12. Google API Services User Data Policy

Content-OS's use and transfer of information received from Google APIs follows the Google API Services User Data Policy, including the Limited Use requirements. Google data is used only to upload and check the creator's own videos, is never used for advertising, and is never transferred to anyone else.

Because Content-OS uses YouTube API Services, the Google Privacy Policy also applies to data Google processes.

13. This website

These information pages set no cookies and contain no analytics. They are hosted by Cloudflare, which processes standard request data, such as IP addresses, to deliver web pages.

14. Changes

If Content-OS changes how it handles data, this page will be updated and the effective date above will change.
